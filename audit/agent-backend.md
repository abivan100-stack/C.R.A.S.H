# Backend Audit — C.R.A.S.H

Scope: `backend/main.py` (506 lines, read in full), `backend/requirements.txt`,
`backend/README.md`, `render.yaml`, plus every frontend call site of the API
(`index.html` inline JS, `app.js`, `notifications.js`, `bot.js`; `report.js` was
checked and makes **no** backend calls — it is the jsPDF report generator).

Domain: server-side correctness, error handling, resilience, data layer, API
contracts, deploy/health. 36 findings.

Verified as **not** defects (checked, no action needed):
- `BOT_AREAS` / `BOT_CAUSES` / `BOT_VEHICLES` match `data/accidents.json` exactly
  (30 / 11 / 8 distinct values, confirmed by extracting the dataset).
- `chr(65+i)` produces A–I for the current 9 columns — correct today (see #7 for
  the latent risk).
- `@app.get("/backend/{rest:path}")` does cover HEAD (Starlette auto-adds HEAD to
  GET routes), so `HEAD /backend/.env` is blocked on Linux.
- `ANTHROPIC_MODEL = "claude-sonnet-4-6"` is a real, active model ID.
- `_normalize_filters` returning an all-null object (never `None`) is handled
  correctly by `bot.js:30-35` `cleanFilters` / `hasActiveFilter`.

## Top priorities

If only five things get fixed before the competition, fix these in order:

1. **#1** — `/health` + `healthCheckPath` (an Atlas hiccup currently takes the whole site down).
2. **#3** — pin `requirements.txt` (an unpinned dep can make the app undeployable on demo day).
3. **#2** — declare `ANTHROPIC_API_KEY` in `render.yaml`.
4. **#4** — add Pydantic validation to `Report` (this alone neutralises #5, #6 and most of #9's blast radius).
5. **#8** — stop serving the repo root (`.git/`, and any root `.env`).

`backend/main.py`, `backend/requirements.txt` and `render.yaml` are all on the
`CLAUDE.md` **OFF-LIMITS** list — none of the fixes above should be applied
without explicit approval first.
