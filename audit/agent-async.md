# Agent audit — Concurrency, async, and network resilience (frontend)

Scope: every `fetch(` / `async` / `await` / `.then(` / `Promise` / `setInterval` /
`setTimeout` / `addEventListener` / `AbortController` / `localStorage` /
`sessionStorage` / `JSON.parse` call site in `app.js`, `notifications.js`,
`report.js`, `bot.js`, `analytics.js`, `compare.js`, `simulate.js`,
`shared/*.js`, `intervention-model.js`, `maptiler.js`, and the inline `<script>`
blocks of `index.html`, `landing.html`, `dashboard.html`, `analytics.html`,
`compare.html`.

Recorded 2026-08-05 against `main` @ `23962be`. Nothing was modified.

**Totals: 30 findings** — 2 critical, 6 high, 12 medium, 10 low.

There are 11 `fetch(` call sites in the repo. 5 have an `AbortController`,
6 have none. All 5 that do have one clear the abort timer at the wrong moment
(finding #1). 3 of 11 skip the `response.ok` check entirely.

## Verified clean

Recorded so a later audit does not re-derive them:

- **All `localStorage` reads and `JSON.parse` of stored values are wrapped in
  `try/catch`** and validate `Array.isArray` before use — `app.js:187-190, 253,
  1796-1802`; `notifications.js:65-91, 272-280`; `analytics.js:474-482`;
  `index.html:9-12, 1351, 2263-2269`; `landing.html:10-13, 808`;
  `dashboard.html:9-14`; `analytics.html:9-14`; `compare.html:7-11`. Only the
  *writes* are a problem (#18). No `sessionStorage` usage anywhere in the repo.
- **No double-submit on the report form.** `setSubmitting(true)`
  (`index.html:2023-2032, 2040`) disables the button before the POST; there is no
  `<form>` element and `afSubmit` is `type="button"` (`index.html:1062`), so
  Enter cannot trigger a native submit.
- **The bot chat is single-flight.** `busy` (`bot.js:316-319`) blocks both the
  click and the Enter paths, and the trailing `.then` at line 335 restores state
  on both success and failure.
- **`setInterval` never stacks.** `notifications.js:363-367` guards with
  `pollStarted`, calls `clearInterval` first, and `pollInFlight` (line 331)
  prevents overlapping requests. This is the only `setInterval` in the codebase.
- **Init guards are in place** for `simulate.js` `wired` (179) / `map` (46),
  `bot.js` `chatInited` (339) / `botMap` (232), `index.html` `reportInited`
  (1414) / `formInited` (1870), and `app.js` `_areaCentroids` (1867) — so the
  repeated `show()` calls at `index.html:1381-1391` do not duplicate listeners.
- **`crash:themechange` listeners do not accumulate**; every registration sits
  behind one of the init guards above or at module scope.
- **`requestAnimationFrame` loops are correctly cancelled** —
  `simulate.js:562` (`cancelAnimationFrame` in `clearProjection`, which
  `renderProjection` calls first at line 639) and `landing.html:862-869`
  (self-terminating on `p < 1`).
- **Debounced resize handlers all clear their prior timer** — `app.js:1731-1734`,
  `analytics.js:455`, `compare.js:412`, `bot.js:365-368`.
- **Toast timers are cleaned up** on dismiss and on cap-overflow eviction
  (`notifications.js:117, 135-140`).
- **Geolocation is properly single-flight**: `runGeolocation`
  (`index.html:1697-1711`) disables the button, uses a `settled` latch against
  double callbacks, and always restores state. `GEO_OPTS` sets a 10 s timeout
  (line 1681), and the Permissions API query at 1774-1779 has both a `.catch`
  and an outer `try/catch`.
