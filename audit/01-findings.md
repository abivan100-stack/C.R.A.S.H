# C.R.A.S.H — Consolidated findings register

Source: eight parallel agent audits (`agent-security.md`, `agent-backend.md`,
`agent-core-logic.md`, `agent-analytics.md`, `agent-async.md`, `agent-html.md`,
`agent-data.md`, `agent-config-tests-obs.md`) — **326 raw rows in, 259 unique findings out**.

`Status` is `VERIFIED` only where the audit lead reproduced the defect by running code;
the evidence is pasted into that row's Failure scenario. Everything else is `UNVERIFIED`.

`[BEHAVIOUR-CHANGE]` on a Proposed fix means applying it changes user-visible output,
a displayed number, on-screen copy, or an API contract — those need a decision, not just a patch.

**Cluster note (XSS):** F001–F003, F009–F015, F049–F051 and F122–F127 are one root cause —
`POST /report` is an unauthenticated, unvalidated write (F016) whose fields are fanned out to
every client by `GET /reports` and interpolated into `innerHTML` with no escaping. `CU.escapeHtml`
exists at `shared/utils.js:29` and is used correctly in `bot.js`/`notifications.js`, never in
`app.js`/`analytics.js`/`simulate.js`/`compare.js`. Each row is a **distinct sink needing its own
edit**; F016 is the single upstream fix that removes exploitability of the whole cluster.
