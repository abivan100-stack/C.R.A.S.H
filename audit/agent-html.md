# Audit — HTML page shells, inline scripts, DOM-injection safety

Scope: `index.html` (2315 lines, read in full), `landing.html` (1002), `dashboard.html` (376),
`analytics.html` (328), `compare.html` (304), plus the DOM-injection paths in `app.js`,
`notifications.js`, `bot.js`, `analytics.js`, `simulate.js`, `compare.js`, `shared/utils.js`.

## Threat model note (applies to findings 1–12)

`POST /report` (`backend/main.py:97-133`) validates the body against a Pydantic model whose
`severity`, `datetime`, `weather`, `cause`, `vehicle`, `area` fields are bare `str` — no
vocabulary, no length cap, no escaping — and the endpoint is unauthenticated. `GET /reports`
(`backend/main.py:136-150`) returns those documents verbatim. On the client,
`app.js:1787-1794 isValidReport()` only checks `typeof === 'string'` for `cause`/`vehicle`/`area`
and does not check `weather` at all, then `app.js:1846-1851` merges the rows straight into
`app.raw`, the single dataset behind the map, the rail, the dossier, the analytics and the
notification feed. **Any string an anonymous attacker can POST is rendered into `innerHTML`
by multiple sinks with no escaping.** This is stored (persistent, cross-device) DOM XSS,
not self-XSS. `escapeHtml` exists in `shared/utils.js:29-33` and is used correctly in
`bot.js` and `notifications.js` — it was simply never applied in `app.js` / `analytics.js` /
`simulate.js`.

## Priority order for fixing

1. **Findings 1, 2, 3** — one-line `CU.escapeHtml` calls each; they close the cheapest,
   highest-impact exploit paths (hover a dot / open a tab).
2. **Findings 4–9** — the remaining unescaped `area`/`cause` sinks.
3. **Finding 22** — vendor Leaflet locally before the live demo.
4. **Findings 36, 37, 38** — the copy that is factually wrong or self-contradicting.
5. **Findings 20, 21** — the `dashboard.html` fork and the cache-buster drift.

A defence-in-depth companion fix, outside this domain but worth naming: constrain
`severity`/`weather`/`cause`/`vehicle`/`area` in the backend `Report` model
(`backend/main.py:97-106`) to the same fixed vocabularies the frontend already uses, with a
length cap on `area`. That kills the whole class at the source rather than sink by sink.
