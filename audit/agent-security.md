# Security audit — C.R.A.S.H

Scope: `backend/main.py`, `maptiler.js`, `bot.js`, `report.js`, `notifications.js`, `backend/.env.example`, `.gitignore`, `backend/.gitignore`, `render.yaml`, `backend/requirements.txt`, `package.json`, plus a repo-wide secret grep, `git log -p` history check, and the sinks in `app.js` / `shared/utils.js` / `index.html` that these files call into.

Note: `report.js` is the **jsPDF report generator**, not the report form. The report form lives inline in `index.html` (~1960–2060); the citizen-report render sinks live in `app.js`.

## Cross-cutting note

Findings #1, #5, #6, #10, #13 and #14 all chain off the same root cause: **`POST /report` is an unauthenticated, unvalidated write into a store that is fanned out to every client and rendered as HTML.** Fixing #6 (vocabulary allowlist + length/range caps in the Pydantic model) and #1 (escape at the render sinks) removes the exploitability of most of the list; #4 (rate limiting) removes the abuse ceiling.
